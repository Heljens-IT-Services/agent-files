# Skill: GitHub Issue Erstellen

## Zweck

Formuliere aus Anforderungen, Analyse oder Ideen ein klar umrissenes Ticket.

## Wann verwenden

- Wenn aus Gespraechen, Notizen oder Analyseergebnissen ein GitHub-Issue werden soll.
- Wenn Arbeit in nachvollziehbare Aufgaben zerlegt werden soll.

## Input

- Problem, Idee oder Analyseergebnis
- optional: gewünschter Scope, Prioritaet, Labels oder Kontext

## Vorgehen

1. Problem oder Bedarf knapp beschreiben.
2. Ziel und Nutzen des Issues formulieren.
3. Scope und Nicht-Ziele trennen.
4. Akzeptanzkriterien definieren.
5. Relevante technische Hinweise oder Risiken angeben.

## Output

- Titel
- Kontext
- Problem
- Ziel
- Scope
- Nicht-Ziele
- Akzeptanzkriterien
- technische Hinweise
- Risiken oder offene Fragen

## Qualitätskriterien

- Ticket muss fuer eine spaetere Umsetzung ausreichend klar sein.
- Akzeptanzkriterien sollen pruefbar formuliert sein.
- Scope soll bewusst begrenzt werden.
